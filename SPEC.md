# Snippet Vault — MVP spec

## Problem & goal

Developers collect useful code snippets in chat logs, notes and old projects, then lose
them. Snippet Vault is one place where a solo developer saves a snippet with a title and
a language, and finds it again in seconds. It should feel instant and stay small.
MVP goal: replace the module 1 `index.html` (localStorage) with four actions on the real
stack: save, list, search, delete. Snippets persist on the API side.

## User stories

### S1. Save a snippet
As a solo developer, I want to save a snippet with a title, a language and the code.
- [ ] Form has three required fields: title, language, code.
- [ ] Submitting a valid form adds the snippet to the top of the list and clears the form.
- [ ] Any blank or whitespace-only field shows one inline error and saves nothing; the API returns `400`.
- [ ] Language is stored trimmed and lowercased (`TypeScript` → `typescript`).
- [ ] If the API fails, the form shows an error and keeps what I typed.

### S2. See my snippets
As a solo developer, I want to see all my saved snippets.
- [ ] On load, the page fetches all snippets from the API and shows them newest first.
- [ ] Each item shows title, language tag and the code in a monospace block.
- [ ] An empty vault shows a "no snippets yet" message.
- [ ] If the fetch fails, the page shows an error message instead of an empty list.

### S3. Find a snippet
As a solo developer, I want to type a word and see only matching snippets.
- [ ] A search box above the list filters as I type; no submit button.
- [ ] A snippet matches when the query is a case-insensitive substring of its title or language; code is not searched.
- [ ] Clearing the box restores the full list; no matches shows a "no snippets match" message.
- [ ] Filtering runs in the browser over the loaded list, with no request per keystroke.

### S4. Delete a snippet
As a solo developer, I want to remove a snippet I no longer need.
- [ ] Each item has a delete button.
- [ ] Clicking it calls `DELETE /snippets/:id` and the item disappears from the list.
- [ ] If the API fails, the item stays and an error message is shown.

## In scope

- One page in `web/`: search box, save form, snippet list with delete buttons.
- Three API routes in `api/` plus the existing `GET /health`.
- Persistence: one JSON file written by the API, path from `SNIPPETS_FILE` (git-ignored).
- Tests: API e2e tests per route (supertest); web component tests per story (Testing Library, fetch mocked).

## Non-goals

- Edit a snippet. Accounts, login, multi-user, sharing.
- Tags beyond the single language field, folders, favourites.
- Full-text search of code content, fuzzy matching, ranking. Pagination.
- Syntax highlighting, copy-to-clipboard.
- A real database. The JSON file sits behind one store class so it can be swapped later.
- Deployment, Docker, CI. Migrating v1 localStorage data.

## Data model

```ts
type Snippet = {
  id: string;        // UUID v4, generated by the API
  title: string;     // trimmed, 1–120 chars
  language: string;  // trimmed, lowercased, 1–40 chars
  code: string;      // 1–20 000 chars, stored verbatim
  createdAt: string; // ISO 8601, set by the API
};
```

## API

Base URL `http://localhost:3000`. JSON in, JSON out. Errors use the NestJS default shape.

| Method | Path             | Body                        | Success                | Errors                          |
|--------|------------------|-----------------------------|------------------------|---------------------------------|
| GET    | `/health`        | –                           | `200 { status: "ok" }` | –                               |
| GET    | `/snippets`      | –                           | `200 Snippet[]`, newest first | `500` store unreadable   |
| POST   | `/snippets`      | `{ title, language, code }` | `201 Snippet`          | `400` invalid field, `500` store unwritable |
| DELETE | `/snippets/:id`  | –                           | `204`                  | `404` unknown id, `500` store unwritable |

`POST` ignores unknown fields, never accepts `id` or `createdAt`; validation messages name the field.

## Milestones

- [ ] **M1 API store + routes.** `SnippetsStore` (JSON file), `POST /snippets`, `GET /snippets`. e2e: create then list, empty vault returns `[]`.
- [ ] **M2 Web list + save.** Page fetches and renders the list newest first; form posts and prepends. Tests with mocked fetch.
- [ ] **M3 Search.** Search box filters by title or language in the browser. Tests: narrows, clears, no-match message.
- [ ] **M4 Delete.** `DELETE /snippets/:id` (`204` / `404`) and a delete button per item. e2e and component tests.
- [ ] **M5 Validation + empty and error states.** API `400`s with field-named messages; web inline errors, "no snippets yet", fetch and delete failure messages. Tests for each.
