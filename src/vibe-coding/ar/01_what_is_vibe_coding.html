ما هي البرمجة بالإحساس حقًّا؟

الوعد، ومواطن الفشل، ولماذا انضباط DevOps هو ما يفصل العرض التجريبي عن منتج قابل للإطلاق.

الوحدة 1 · العقلية — مع أوّل بناء عملي لك.

مبتدئ الأساسيات يتضمّن مختبرًا ~40 دقيقة

ماذا ستتعلّم

  • تعريف البرمجة بالإحساس — وما يفصلها عن «نفايات الذكاء الاصطناعي» المتهوّرة
  • فهم لماذا هي قوية فعلًا وليست مجرد ضجيج
  • التعرّف على مواطن الفشل الستة التي تكسر المشاريع المولّدة بصمت
  • كيف يقابل كل فشلٍ ممارسةً معروفةً في DevOps تعالجه
  • وعد هذه الدورة: ابنِ بالإحساس، وأطلق بالانضباط
  • مختبر عملي: ابنِ خزنة مقتطفات مصغّرة، وأطلق موطن فشلٍ، وأنشئ أوّل إيداع Git لك

المتطلبات المسبقة: لا شيء. إن سبق أن طلبت من ذكاء اصطناعي كتابة شيفرة، فأنت جاهز.

إذًا، ما هي «البرمجة بالإحساس»؟

شاع المصطلح مطلع عام 2025 على يد الباحث في الذكاء الاصطناعي أندريه كارباثي، الذي وصف طريقة جديدة لبناء البرمجيات: «تستسلم تمامًا للإحساس» — تصف ما تريد بلغة طبيعية، فيكتب المساعد الشيفرة، وتشغّلها، وتوجّه بمزيد من الكلمات بدل تعديل كل سطر بنفسك.

بدل التفكير بالصياغة البرمجية، تفكّر بالـمقصد:

You: "Build me a web page that lets me save code snippets with a title and a language tag, stored in a small database, with a search box up top." AI: ...generates the routes, the HTML, the database schema, the search logic... You: "Nice. Now make the search filter by language too, and add a copy button."

هذا هو «الإحساس». سريع وممتع، ويتيح لشخص واحد بناء أشياء كانت تتطلّب فريقًا. لكن لاحِظ: في هذا الحوار، لم يكتب أحدٌ اختبارًا، ولا أنشأ إيداعًا، ولا تحقّق من أمان شيفرة قاعدة البيانات المولّدة. هذه الفجوة هي كل سبب وجود هذه الدورة.

البرمجة بالإحساس ليست «نفايات ذكاء اصطناعي»

البرمجة بالإحساس المُتقَنة مهارة هندسية حقيقية: مقصد واضح، وحلقات تغذية راجعة سريعة، ومراجعة دائمة. أما «النفايات» فهي أن تلصق ما أنتجه النموذج مباشرةً في الإنتاج دون قراءته. الأدوات نفسها — والنتيجة مختلفة تمامًا. هذه الدورة عن الأولى.

لماذا هي قوية فعلًا

المتشكّكون ليسوا على خطأ تام — ولا المتحمّسون. فعند استخدامها جيدًا، تمنح البرمجة المدعومة بالذكاء الاصطناعي مزايا حقيقية قابلة للقياس:

ما الذي يتغيّرلماذا يهمّ
سرعة النسخة الأولىنموذج أوّلي يعمل خلال دقائق لا أيام. تكتشف ما تريده فعلًا حين تراه يعمل.
حاجز دخول أخفضيمكنك البناء بلغة أو إطار غير مألوف لأن المساعد يملأ الفجوات.
عناء أقل مع الشيفرة المتكرّرةالـ80% المتكرّرة (CRUD، النماذج، الإعداد) تُكتب لك، فتصرف طاقتك على الـ20% المهمّة.
شريك لا يكلّيشرح الشيفرة، ويقترح الأسماء، ويلتقط الأخطاء الواضحة — في الثانية صباحًا، مجانًا.

الخلاصة الصادقة

تجعل مساعدات الذكاء الاصطناعي الوصول إلى عرضٍ يعمل أسهل بمراحل. لكنها لا توصلك تلقائيًّا إلى منتجٍ قابل للإطلاق. المسافة بينهما هي بالضبط ما دُرّب عليه المهندس المحترف — وما تسدّه هذه الدورة.

أين تنكسر البرمجة بالإحساس بصمت

نادرًا ما تظهر هذه الإخفاقات في العرض. تظهر بعد أسبوع — حين تعجز عن إعادة إنتاج خطأ، أو التراجع عن تغيير، أو تكتشف أن مفاتيحك السرّية على GitHub. وهذه الستة أشدّها إيلامًا:

#موطن الفشلكيف يبدو
1«يعمل مرة واحدة»العرض يعمل، لكن لا اختبارات، فيكسر التغيير التالي شيئًا بصمت دون أن ينتبه أحد.
2لا تراجعكل شيء في مجلد واحد بلا تحكّم بالإصدارات. تعديلٌ سيّئ من الذكاء الاصطناعي يطمس شيفرةً تعمل فتضيع.
3شيفرة مُهلوَسةيستدعي المساعد بثقةٍ دالّةً أو واجهةً برمجيةً غير موجودة، أو يستخدم نمطًا قديمًا.
4ثغرات أمنية صامتةحقن SQL، أسرار مكتوبة صراحةً، غياب التحقّق من المدخلات — الشيفرة تعمل، ولهذا لا ينظر أحد أعمق.
5تآكل السياقمع نموّ المشروع يفقد المساعد الخيط، ويناقض قرارات سابقة، ويكرّر المنطق.
6«يعمل على جهازي»لا حاويات ولا بيئة محدّدة — فيعمل لديك ولا يعمل في أي مكان آخر.

الخيط المشترك

كل واحد من هذه إخفاقٌ في الانضباط، لا في الذكاء الاصطناعي. فالمساعد فعل ما طلبته؛ لكن العملية حوله بلا حواجز أمان. والخبر السار: حقلنا حلّ هذه المشكلات منذ سنوات — والحلّ اسمه DevOps.

العلاج: انضباط DevOps

DevOps مجموعة ممارسات لبناء البرمجيات وشحنها بموثوقية وقابلية للتكرار. لكل موطن فشلٍ أعلاه ترياقٌ مباشر من DevOps — وهذا التقابل هو العمود الفقري لكل الدورة:

موطن الفشلممارسة DevOps التي تعالجهأين في الدورة
«يعمل مرة واحدة»الاختبارات الآلية + التكامل المستمرالوحدتان 6 و9
لا تراجعالتحكم بالإصدارات (Git)الوحدة 4
شيفرة مُهلوَسةمراجعة كل تغيير + الاختباراتالوحدتان 4 و6
ثغرات أمنيةبوابات الجودة وفحص الأمانالوحدة 7
تآكل السياقالتخطيط أولًا + إيداعات صغيرةالوحدتان 3 و4
«يعمل على جهازي»الحاويات + البنية التحتية ككودالوحدتان 8 و10

فلسفة الدورة في سطر

ابنِ بالإحساس. أطلق بالانضباط. استخدم الذكاء الاصطناعي للتحرّك بسرعة، واستخدم ممارسات DevOps لتضمن أن ما أطلقته صحيحٌ وآمنٌ وقابل للتكرار وللتراجع. ولا غنى عن أيّ من النصفين.

تملك أساسيات DevOps مسبقًا؟

تعيد هذه الدورة استخدام معايير الهندسة من مختبر DevOps — Docker وGitHub Actions وTerraform وAnsible وPrometheus وGrafana — لنبقى مركّزين على البرمجة مع الذكاء الاصطناعي بالطريقة الصحيحة. وعند حوسبة التطبيق أو إعداد CI سنربط مباشرةً بوحدة مختبر DevOps المقابلة بدل إعادة تدريسها.

ماذا ستبني

عبر الوحدات الإحدى عشرة القادمة ستبرمج بالإحساس تطبيقًا صغيرًا لكنه حقيقي — خزنة مقتطفات (احفظ مقتطفات الشيفرة بعنوان ووسم لغة وبحث) مبنيّة بواجهة React وواجهة برمجية بـNestJS (Node) — مستخدمًا Claude Code كمساعد ملموس. وكل مبدأ يصلح لأي أداة، فـCursor أو Copilot أو أي مساعد آخر يفي بالغرض.

ستأخذ ذلك التطبيق الواحد من مجلد فارغ إلى نشرٍ يختبر نفسه عند كل تغيير ويبلّغ عن صحّته. وبحلول المشروع الختامي، ستأخذ فكرةً جديدة عبر الدورة ذاتها بنفسك.

مختبر عملي: أوّل «إحساس» لك (وأوّل حاجز أمان)

حان وقت البناء. ستُجري حلقة البرمجة بالإحساس كاملةً مرّة واحدة، وتُطلق موطن فشلٍ بيدك، ثم تضع أوّل حاجز أمان من DevOps — التحكم بالإصدارات. وستسلّم مستودع Git صغيرًا في النهاية.

ما تحتاجه

أيّ مساعد ذكاء اصطناعي لديك — Claude Code أو Cursor أو Copilot Chat أو محادثة ويب مثل claude.ai / ChatGPT — ومتصفّح ويب، وGit مثبّتًا. هذا كل شيء. (سلسلة أدوات المشروع الكاملة — Node وReact وNestJS — تأتي في الوحدة 2؛ اليوم نبقى خفافًا عمدًا.)

1

أنشئ مجلد المشروع

أنشئ مجلد التطبيق الذي ستنمّيه طوال الدورة:

mkdir snippet-vault cd snippet-vault
2

ابنِ النسخة الأولى بالإحساس

أعطِ مساعدك هذا الطلب بالضبط (يمكنك ترجمته إلى العربية إن شئت)، واحفظ ما ينتجه باسم index.html:

Build a single-file index.html "snippet vault": a page where I can save code snippets, each with a title and a language tag, kept in the browser with localStorage. Show saved snippets in a list with a search box at the top that filters by title. Plain HTML, CSS and JavaScript in one file, no build step.
3

شغّله

انقر نقرًا مزدوجًا على index.html لفتحه في متصفّحك. أضف مقتطفين أو ثلاثة وجرّب البحث. تهانينا — لقد برمجت للتوّ تطبيقًا يعمل بالإحساس.

4

أطلق موطن فشلٍ — عن قصد

اطلب من المساعد تغييرًا — مثل «اجعل البحث يطابق وسم اللغة أيضًا» — والصق النسخة الجديدة فوق index.html دون قراءتها. أعد التحميل. هل انكسر شيء آخر؟ هل تستطيع استعادة النسخة القديمة؟ (لا تستطيع — هذا موطن الفشل رقم 2، «لا تراجع». وسنعالجه الآن.)

5

ضع أوّل حاجز أمان: Git

امنح نفسك زرّ تراجعٍ إلى الأبد:

git init git add . git commit -m "First vibe: snippet vault v1"

من الآن فصاعدًا كل تغيير قابل للاسترجاع. هذه أعلى عادةٍ قيمةً في الدورة كلها — وقد فعلتها في الوحدة 1.

6

تأمّل، ثم أودِع تأمّلك

أنشئ ملف REFLECTION.md في المجلد وأجب، بأسطرٍ قليلة لكلٍّ:

  • الصق الطلب الذي استخدمته بالضبط.
  • أيّ مواطن الفشل الستة أصبته أو كِدت؟
  • لكلٍّ منها، أيّ ممارسة DevOps من الجدول أعلاه تمنعه؟
  • في جملة واحدة: ما الذي يجعل هذا التطبيق جديرًا بالثقة بما يكفي لإطلاقه؟
git add REFLECTION.md git commit -m "Add module 1 reflection"

ما الذي تسلّمه

مستودع Git snippet-vault/ — يحتوي index.html وREFLECTION.md، بإيداعين على الأقل. تحقّق من نفسك بهذه القائمة قبل التسليم:

  • git log يُظهر إيداعين على الأقل
  • index.html يفتح ويعمل في المتصفّح
  • REFLECTION.md يتضمّن طلبك ويربط موطنَي فشلٍ على الأقل بممارسات DevOps
  • تستطيع أن تشرح شفهيًّا ما الذي منحك إيّاه git commit
