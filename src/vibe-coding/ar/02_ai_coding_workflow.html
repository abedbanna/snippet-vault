سير عملك مع المساعد

أعِدّ مساعدك والعادات التي تحوّله إلى شريكٍ موثوق — لا آلة حظّ.

الوحدة 2 · الإعداد، والسياق، والصياغة، والتوجيه.

مبتدئ سير العمل يتضمّن مختبرًا ~50 دقيقة

ماذا ستتعلّم

  • إعداد بيئة حقيقية (Node.js) ومساعد ذكاء اصطناعي وكيليّ — Claude Code مثالًا؛ وأي مساعد يفي
  • معرفة نوعَي المساعد ومتى تلجأ لكلٍّ
  • فهم لماذا السياق هو كل شيء، وكيف تغذّيه بملف سياق المشروع
  • صياغة طلباتٍ تُنتج شيفرةً تعمل: هدف، قيود، معايير قبول، والخطة أولًا
  • التوجيه بدل المقامرة: تغييرات صغيرة، مراجعة دائمة، وإعادة ضبط المساعد المشوّش
  • مختبر عملي: ثبّت أدواتك، أضِف ملف سياق، وابنِ هيكل خزنة المقتطفات بطلبٍ منظَّم

المتطلبات المسبقة: الوحدة 1 — ينبغي أن يكون لديك مستودع snippet-vault من المختبر الأول.

تعرّف على مساعدك

تأتي مساعدات البرمجة بالذكاء الاصطناعي في شكلين عريضين. ستعتمد على أحدهما محرّكًا رئيسيًّا، لكن من المفيد معرفة كليهما:

النوعماذا يفعلأمثلة
مساعد محادثةتلصق الشيفرة وتنسخ الإجابات. بسيط، لكنه لا يرى مشروعك ولا يشغّل شيئًا.claude.ai، ChatGPT
وكيليّ / داخل المحرّريقرأ ملفاتك ويعدّلها مباشرةً، ويشغّل الأوامر، ويعمل عبر المستودع كلّه. هنا تصبح البرمجة بالإحساس قوية.Claude Code، Cursor، Copilot

سنستخدم Claude Code مثالًا ملموسًا

Claude Code مساعد وكيليّ يعيش في الطرفية (Terminal) — يقرأ مستودعك، ويعدّل الملفات، ويشغّل الأوامر بموافقتك. مناسبٌ لدورةٍ عن الإطلاق، لأن الطرفية هي مكان البناء والاختبار والنشر. وكل ما تتعلّمه هنا ينطبق مباشرةً على Cursor أو Copilot — سير العمل نفسه، تختلف الأزرار فقط.

تصلح لأي أداة، عن قصد

لا تتعلّق بأداة واحدة. المساعدات تتغيّر شهريًّا؛ أمّا العادات في هذه الوحدة — السياق، والطلبات الواضحة، والتغييرات الصغيرة المُراجَعة — فهي ما يجعلك منتجًا فعلًا، وتنتقل معك إلى أيّ أداة تالية.

السياق هو كل شيء

لا يعرف المساعد إلا ما في نافذة سياقه — طلبك، مع ما يراه من ملفات الآن. لا يقرأ أفكارك، ولا يتذكّر الأسبوع الماضي، ولا يخمّن أعرافك. ومعظم لحظات «الذكاء الاصطناعي كتب شيفرةً سيّئة» هي في الحقيقة لحظات سياقٍ ناقص.

ملف سياق المشروع

العلاج ملفٌ صغير في جذر مستودعك يقرأه المساعد تلقائيًّا، يصف المشروع مرّة واحدة كي لا تكرّر نفسك كل طلب. ولكل أداة اسمها له:

المساعدملف السياق
Claude CodeCLAUDE.md
Cursor.cursorrules
Copilot.github/copilot-instructions.md

الجيّد منه قصيرٌ وملموس — التقنية، والبنية، والأعراف، وبعض «الممنوعات»:

# Snippet Vault A small app to save code snippets (title + language tag + search). ## Stack - Front end: React (in web/) - API: NestJS (Node) (in api/) - One repo, two apps (a monorepo). ## Conventions - TypeScript everywhere. Small, focused commits. - Every feature needs a test before it's "done". ## Don't - Don't add a feature I didn't ask for. - Don't hard-code secrets. Don't skip error handling.

قاعدة عملية

إن وجدت نفسك تكتب الشرح ذاته للمساعد مرّتين، فمكانه ملف السياق. اكتبه مرّة؛ يقرأه المساعد في كل مرّة.

صياغةٌ تُنتج شيفرةً تعمل

الطلب الغامض يعطي تطبيقًا غامضًا. والطلب الجيّد له أربعة أجزاء — وقاعدةٌ ذهبية واحدة:

الجزءماذا تقول
الهدفما تريده، في جملة واحدة.
القيودالتقنية، والأسلوب، والمكتبات المطلوبة أو الممنوعة.
معايير القبولكيف ستعرف أنه اكتمل — السلوك الذي ستتحقّق منه.
خارج النطاقما لا يُمَسّ أو يُبنى.

القاعدة الذهبية: لأيّ أمرٍ غير تافه، اطلب خطةً قبل الشيفرة. اقرأ الخطة، صحّحها، ثم دعه يبني. فإصلاح خطةٍ أرخص بكثير من إصلاح كومة ملفاتٍ مولّدة.

طلب غامض

«اصنع لي تطبيق مقتطفات.» → ستحصل على شيءٍ ما، بإطارٍ ما، بخياراتٍ لم تتّخذها ولا يمكنك توقّعها.

طلب منظَّم

«الهدف: بناء هيكل خزنة المقتطفات كـmonorepo. القيود: React في web/، وNestJS في api/، وTypeScript. القبول: يبدأ كل تطبيق بأمرٍ واحدٍ موثَّق؛ بلا ميزاتٍ بعد. خارج النطاق: لا تنفّذ المقتطفات أو التنسيق بعد. أولًا، أرِني خطة المجلدات — ولا تكتب شيفرةً حتى أقول go.»

وجِّه، لا تُقامِر

الفرق بين المحترف والمقامر ليس الطلب — بل ما يحدث بعده. أربع عادات تُبقيك مسيطرًا:

العادةلماذا
اقرأ كل تغييرلا تقبل شيفرةً لم تنظر إليها. هذه العادة وحدها تمنع معظم الكوارث.
أبقِ التغييرات صغيرةشأنٌ واحد في المرّة، ثم أودِع. التغييرات الصغيرة قابلة للمراجعة؛ والضخمة تخفي العلل.
صحّح مبكرًااتجاهٌ خاطئ؟ توقّف وأعد التوجيه عند أول علامة، لا بعد عشرة تعديلاتٍ فوقه.
أعد الضبط عند التشوّشإن ناقض المساعد نفسه أو دار في حلقة، امسح السياق وابدأ المهمّة من جديد. ذاك تآكل السياق — موطن الفشل رقم 5.

القاعدة التي لا تكسرها أبدًا

لا تقبل تغييرًا لم تقرأه. «لقد اشتغل، إذًا لا بأس» هو بالضبط كيف تُشحن العلل الصامتة والثغرات الأمنية. أنت المراجِع؛ والذكاء الاصطناعي هو المبتدئ. الوحدات اللاحقة (الاختبارات، بوابات الجودة) تضيف نسخًا احتياطية آلية — لكن عيناك أولًا.

مختبر عملي: أعِدّ مساحة عملك وابنِ هيكل التطبيق

ستثبّت أدواتك، وتُعرّف المساعد بالمشروع عبر ملف سياق، ثم تستخدم طلبًا منظَّمًا لبناء هيكل خزنة المقتطفات الحقيقية — مراجعًا ومودِعًا وأنت تمضي. وستسلّم المستودع المحدَّث.

ما تحتاجه

مستودع snippet-vault من الوحدة 1، بالإضافة إلى Node.js LTS ومساعدٍ وكيليّ (Claude Code مُستحسَن؛ وCursor أو Copilot يفيان).

1

ثبّت Node.js وتحقّق

ثبّت إصدار LTS من nodejs.org، ثم أكّد:

node -v npm -v
2

ثبّت مساعدك

لـClaude Code، ثبّته وشغّله داخل مجلد المشروع:

npm install -g @anthropic-ai/claude-code cd snippet-vault claude

تستخدم Cursor أو Copilot؟ افتح مجلد snippet-vault في المحرّر فحسب — وبقيّة المختبر متطابقة.

3

امنح المساعد سياقًا

أنشئ ملف سياق في جذر المستودع (CLAUDE.md لـClaude Code، أو ما يقابله في أداتك) مستخدمًا القالب من قسم السياق أعلاه. عدّله ليلائم مشروعك.

4

اطلب خطةً — قبل أيّ شيفرة

الصق الطلب المنظَّم أدناه. حين يردّ المساعد بخطة مجلدات، اقرأها واعترض على ما لا يعجبك. عندها فقط قل «go».

Goal: scaffold the snippet vault as a monorepo. Constraints: React front end in web/, NestJS API in api/, TypeScript. Acceptance: each app starts with one documented command; no features yet. Out of scope: don't implement snippets, search, or styling yet. First show me the folder plan. Do not write code until I say "go".
5

ابنِ الهيكل، وراجع، وشغّل

دعه ينشئ الهيكل. اقرأ التغيير قبل القبول. ثم شغّل كل تطبيق للتأكّد من عمله (سيخبرك المساعد بالأوامر الدقيقة، غالبًا بنحو):

# API cd api && npm install && npm run start:dev # Web (in a second terminal) cd web && npm install && npm run dev
6

أودِع، ثم تأمّل

أودِع الهيكل وملف السياق:

git add . git commit -m "Scaffold monorepo (web + api) and add context file"

ثم أضِف إلى REFLECTION.md: الصق ملف سياقك وطلبك؛ ودوّن شيئًا واحدًا أخطأ فيه المساعد أو افترضه وكيف وجّهته؛ وفي سطرٍ واحد، كيف تفوّق طلبك المنظَّم على «اصنع لي تطبيق مقتطفات». ثم أودِعه.

ما الذي تسلّمه

مستودع snippet-vault المحدَّث. تحقّق من نفسك قبل التسليم:

  • المستودع فيه ملف سياق (CLAUDE.md / .cursorrules / تعليمات Copilot)
  • مجلّدا web/ وapi/ موجودان ويبدأ كل تطبيق بأمرٍ واحد
  • إيداعات جديدة للهيكل وللتأمّل
  • REFLECTION.md يتضمّن طلبك، والخطة التي وافقت عليها، وتوجيهًا واحدًا قمت به

مسرد مصغّر

المصطلحالمعنى المبسّط
نافذة السياقكل ما يستطيع النموذج «رؤيته» الآن — طلبك مع الملفات الظاهرة. وخارجها يكون النموذج أعمى.
مساعد وكيليّذكاء اصطناعي يقرأ/يعدّل الملفات ويشغّل الأوامر مباشرةً، لا مجرّد محادثة.
ملف السياقملفٌ في المستودع (CLAUDE.md، .cursorrules…) يقرأه المساعد ليتعلّم مشروعك مرّة واحدة.
الهيكل (Scaffold)الهيكل الفارغ للمشروع — مجلّدات، إعداد، «hello world» — قبل الميزات الحقيقية.

الخلاصة وما التالي

صار لديك الآن

بيئةٌ تعمل، ومساعدٌ وكيليّ يعرف مشروعك عبر ملف سياق، ووصفةُ طلبٍ قابلة للتكرار (هدف / قيود / قبول / خارج النطاق، والخطة أولًا)، وعادات التوجيه التي تُبقيك مسيطرًا — مع هيكل monorepo (React + NestJS) مُودَع.

التالي: الوحدة 3 — التخطيط أولًا. قبل بناء الميزات، نحوّل الفكرة الغامضة «خزنة مقتطفات» إلى مواصفةٍ واضحةٍ قابلة للتنفيذ يتّبعها المساعد دون تِيه.
